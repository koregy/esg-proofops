# 제출용 배포와 시연

배포 주소: https://esg-proofops-koregy.vercel.app

2026-09-29 개발자 A 저장소 `tskwak111/esg-proofops-submission`의 공개 화면을 통합하고, 후속 `6d9eb1a73cb887a42910f2fe17ab49622054b87d`까지 홈·메뉴·강조색 변경을 반영했습니다. 기존 PDF 분석 연결, 원문 검증 전 보류 표시와 저장 결과의 실제 수치는 유지합니다. 이 문서는 이전 배포 미정 기록보다 우선하는 현재 공개 배포 상태입니다.

제출 코드: https://github.com/koregy/esg-proofops/tree/submission/deadline-20260929 · PR: https://github.com/koregy/esg-proofops/pull/1

## 바로 시험하기

1. `/analyze`에서 PDF를 선택합니다. 구역 자동 탐색이 끝날 때까지 기다립니다.
2. 분석할 쪽은 PDF 뷰어 기준 물리적 쪽 번호입니다. POSCO 2025 보고서는 먼저 `33`을 입력하면 됩니다.
3. 운영자가 별도로 전달한 접근 키를 입력하고 실시간 분석을 시작합니다. Upstage API 키를 입력하는 칸이 아닙니다.
4. 주장 인용, 쪽 번호, 텍스트 일치 여부, 등급 보류 사유를 확인합니다.

기업 등록이나 작업공간 생성 없이 공개 후보 추출을 시험할 수 있습니다. 최대 60쪽을 선택하며 10쪽 이하로 나누어 순차 처리합니다. 큰 이미지로 4MB를 넘는 쪽은 명시적으로 건너뜁니다. 요청당 환경 관련 문단 최대 16개, 주장 최대 5건을 대상으로 하므로 보고서 전수 분석 결과가 아닙니다. 기본 자동 구역 분류는 수정 가능한 추천이며 정확한 목차 판정을 보장하지 않습니다.

`/live`는 붙여 넣은 문장 분석입니다. PDF 원문 검증이 없는 결과에는 등급을 부여하지 않습니다. `/demo`와 `/report/naver`는 저장된 NAVER 부분 분석 결과입니다. 331개 주장 중 저장 등급이 있는 것은 17개이며, 314개는 보류입니다. 기아 사례 화면은 개발자 A가 제공한 시연 데이터로 독립 검증 완료를 뜻하지 않습니다.

## 배포 구성

- React 정적 화면: `VITE_DEMO_STATIC=true pnpm build`
- Vercel Python 함수: `/api/live-report`, `/api/live-claim`
- 서버 전용 환경변수: `UPSTAGE_API_KEY`, `DEMO_ACCESS_CODE`
- Upstage Document Parse와 Solar Pro 3를 사용합니다. 브라우저에는 공급자 키를 전달하지 않습니다.
- 공개 PDF API는 요청별 비용·쪽수·출력 제한을 적용하며 누적 사용 장부, 원문 PDF 영속 저장, 계정별 작업공간을 제공하지 않습니다.
- 전체 원문·좌표·가시성 검증, 영속 감사 기록과 워커 실행은 별도 로컬 구성에 남아 있습니다. AWS 운영 배포를 완료한 상태는 아닙니다.

로컬 운영자 접근 키 파일은 `.local/deployment/demo-access.txt`입니다. 비공개 파일이며 커밋하거나 공개 문서에 값을 붙여 넣지 않습니다. 심사위원에게는 별도 전달해야 새 PDF와 문장 분석을 실행할 수 있습니다. 저장 결과 화면은 접근 키 없이 볼 수 있습니다.

## 확인한 결과

- 공개 주요 경로 8개 HTTP 200.
- 접근 키 없는 PDF 요청 HTTP 403.
- 실제 POSCO PDF 33쪽의 서버 요청 HTTP 200, 약 9.83초, 주장 후보 5건 반환. 이 요청에서는 원문 텍스트 일치가 확인되지 않아 태깅·등급을 보류했습니다.
- TypeScript 검사와 Vercel 프로덕션 빌드 통과.
- 실제 Chrome에서 POSCO 원본 133쪽 PDF 업로드 → 33쪽 선택 → 결과 5건 표시 확인(17.3초). 이 브라우저 요청에서는 PDF 텍스트 일치와 요소 후보가 표시됐으며, 모든 등급은 보류였습니다. 브라우저 실행 오류는 없었습니다.
- 서버리스 PDF·문장 처리 및 OCR 재생 캐시 회귀 검사 46개 통과. 문장 분석의 잘린 출력·잘못된 JSON·태깅 서비스 실패는 자동 재시도 없이 미완료 단계와 보류 사유를 남깁니다. 최초의 간헐 HTTP 502는 재현되지 않아 근본 원인은 확정하지 않았습니다.
- A 최신 화면 통합 후 공개 화면 검사 10개, 확장 시연 검사 16개, 저장 재생 데이터 검사 3개 통과. 저장 등급·보류 상태와 외부 요청 제한도 검사합니다.
- 최신 배포의 데스크톱·모바일 14개 경로씩 28개 화면 표시, 검토 큐·검토 모드·메뉴 이동을 확인했습니다. 실제 문장 분석도 등급 보류로 표시됐으며, 모의 부분 실패 응답에서 실패 단계를 완료로 표시하지 않는 것도 확인했습니다.

후보 추출 성공을 원문 검증 완료 또는 확정 판정 성공으로 해석하지 않습니다. 모델 출력과 원문 대조 결과에 따라 잠정 후보와 보류 사유가 달라질 수 있습니다.
